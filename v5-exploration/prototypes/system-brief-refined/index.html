Software Factory

Governed agentic engineering · control plane
IASDP Application → platform · no product interface claimed

Agents can produce work. They cannot grant it authority.

The flagship. A control plane holding planning, execution, verification, review, and release as separate domain responsibilities — a model that fails, stalls, or overstates cannot become an approval.

Durable domain · SQLite
plansrevisionswork itemsruns verification evidencereviewsapprovalsrelease lineage

Written in TypeScript.

Provider-neutral worker ports ↓ the domain does not know which vendor answers
Disposable workers · process adapters
Codex CLIClaude Code CLI

Workspace-scoped, default-deny environment. Replaceable.

Durability
Workers, processes, and sessions are disposable. The domain above them is not.
Fail-closed parsing
Reviewer verdicts are parsed strictly. Ambiguous output never defaults to pass.
Supervision

04

JointLedger

Upstream backend extension · runtime integration
IASDP Services → platform · no frontend

A shared ledger is a permissions problem before it is a screen.

Two evidenced contributions to a self-hosted accounting application written by someone else: the local Docker Compose and PostgreSQL runtime on the default branch, and on a feature branch a backend extension turning a single-owner ledger into a shared one — against a schema and invariants that were inherited, not chosen.

  1. Book · BookMember · BookInvitationNew models over the upstream schema
  2. Book services and APIsOwner, editor, and viewer checks, with role tests
  3. Book scopingAccounts, categories, and tags resolved per book
Inherited, not authored
  • Upstream accounting engine and Vue interface — not Hakan's work.
  • No shared-book frontend, no book selector.
  • Invitations are schema and status infrastructure only.
  • Transactions carry a bookId, but reads and writes stay on the original owner-scoped path.
Migration safety
Personal-book creation is deterministic and the backfill idempotent. Every record lands in exactly one book; a second run creates no duplicate.
Runtime
Compose service definitions and a PostgreSQL container with a persistent volume — the environment the extension is verified against.
Status
Four commits ahead on a feature branch. Unmerged and unreleased.
03 / AI engineering

Agents participate. The system keeps authority.

The workflow matters more than the tool brands. Providers are adapters and can be swapped; the plan, the evidence, and the release decision cannot.

Position

Model confidence is not system evidence.

Agents work inside a system whose durable state and release authority never depend on them. Model text is recorded as evidence, never read as acceptance.

Zero autonomous release authority
Objective → accountable release
  1. 01SpecifyObjective, constraints, acceptance criteria
  2. 02PlanDependency graph, deterministically validated
  3. 03ApproveApproval binds to one plan revision
  4. 04ImplementWorkspace-scoped worker, default-deny environment
  5. 05VerifyFixed executable and argv; process facts, not prose
  6. 06ReviewIndependent principal, strict fail-closed verdict
  7. 07ReleaseContent-addressed evidence snapshot
Human decision Agent work Deterministic process
Repair ↺

A review that returns changes required sends the work back to implementation for a bounded number of cycles.

Bounded
Durable stateEvery plan, run, verdict, and approval is persisted before its process exits.
Deterministic evidenceVerification runs a fixed command. Its result is stored apart from anything a model wrote about it.
SupervisorZero-spend policy and persisted backoff, so resource limits outlive a restart.

A newer implementation invalidates prior verification, review, and approval. Nothing carries forward on reputation.
