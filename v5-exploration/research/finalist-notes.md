# Finalist notes

## Finalist 1 — System Brief

The recommended direction. A recruiter can identify Hakan's primary identity in seconds, while an engineering manager can read responsibility, project decisions, platform context, and AI assurance at increasing depth. Production should preserve the hierarchy and remove technologies rather than add them.

GitHub implementation: high feasibility. Translate the responsibility map, case decisions, and assurance panel into a small sequence of local SVGs. Use `<picture>` for dark/light variants. Keep only a subtle animated route token and a static/reduced-motion fallback. Avoid turning the full prototype into one excessively tall asset.

## Finalist 2 — Architecture Dossiers

The strongest proof-led direction. It makes architecture decisions—transactional consistency, local-first persistence, and governed agentic execution—the center of the profile.

GitHub implementation: high feasibility. Each dossier becomes an individual GitHub-safe SVG case plate with selectable Markdown/HTML context and descriptive alt text. The editorial typography must be sized for GitHub's narrow profile column, and mobile variants should stack the case path instead of shrinking it.

## Finalist 3 — Assurance Loop

The strongest AI engineering direction. It communicates that models participate within durable, independently verified, human-authorized systems.

GitHub implementation: feasible with more production effort. Split the decision, execution, evidence, and workflow views into separate SVG panels. Animate only the handoff/return path. Include static fallbacks and keep the React/TypeScript identity above the AI system so the profile does not read as tooling-first.

## Evidence method

All six full HTML/CSS prototypes were rendered and measured in Chrome at 1440 × 1000 and 390 × 845 in both themes. `render-audit.json` records 24 clean variants with no broken images or horizontal overflow. Chrome produced initial full-page captures for A–C; its external capture channel later timed out on the longer pages. The finalist PNGs are deterministic, code-native evidence renders generated from the refined finalist compositions by `scripts/render-evidence.ps1`; the complete browser prototypes remain the authoritative interactive previews.
